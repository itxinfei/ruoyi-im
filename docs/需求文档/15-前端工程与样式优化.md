# 15 前端工程与样式优化

> **本文档规定前端工程的骨架屏策略、滚动容器规则、性能优化清单**。关联模块：02-研发红线与编码规范.md、12-UI交互规范与红线.md。

## 一、骨架屏规范

### 1.1 使用原则

- 仅当加载时间 >300ms 时显示骨架屏（<300ms 不显示以避免闪烁）
- 骨架屏形状与实际布局 1:1 对齐（矩形/圆形/列表项 shape）
- 骨架屏有细微的 shimmer 动画（CSS animation，不消耗 JS 主线程）

### 1.2 骨架组件设计（与实际组件 companion）

| 对应组件 | 骨架形态 | 尺寸 |
|---------|---------|------|
| 会话列表项 | 头像圆 + 两行文字横条 | 头像 40×40、文字宽 120px/80px |
| 聊天窗口 | 头像圆 + 气泡方块（左一右一） | 气泡高 40-80px 随机 |
| 通讯录 | 头像圆 + 一行文字 | 头像 32×32 |
| 日历月视图 | 7×6 日期格子 | 每格 40×40 |
| 审批列表 | 三行文字横条 | 宽度 100%/80%/60% |

```scss
.skeleton {
  background: linear-gradient(90deg, #f0f0f0 25%, #e0e0e0 50%, #f0f0f0 75%);
  background-size: 200% 100%;
  animation: shimmer 1.5s infinite;
}

@keyframes shimmer {
  0% { background-position: 200% 0; }
  100% { background-position: -200% 0; }
}
```

### 1.3 骨架屏实现注意事项

- 骨架组件应与实际组件放在同一目录，命名规则 `XxxSkeleton.vue`
- 骨架屏不触发任何业务逻辑，纯展示
- 使用 `v-if` 控制骨架屏与真实内容切换，不使用 `v-show`（骨架屏不保留 DOM）
- 骨架屏颜色使用设计令牌 `var(--dt-bg-secondary)` 和 `var(--dt-bg-tertiary)`

## 二、滚动容器规则

### 2.1 基础规则

- 所有可滚动容器必须 `overflow-y: auto`（禁止 `overflow: scroll` 始终显示滚动条）
- 滚动容器加 `min-height: 0` 防止 flex 子项撑爆
- 一个区域只保留一个主滚动容器，避免"双滚动条"与滚动同步问题

### 2.2 滚动位置策略

| 场景 | 行为 |
|------|------|
| 切换会话 | 滚动位置重置到顶部 |
| 从消息列表返回会话列表 | 保持原滚动位置 |
| 全局搜索结果加载 | 滚动位置重置到顶部 |
| 切换到已访问过的模块 | 保持上次滚动位置（SessionStorage） |

### 2.3 骨架方法论（旧 doc75 恢复）

**布局骨架优先原则**：

1. 一级布局：`L1 导航 + L2 列表/侧栏 + L3 主内容`
2. 主内容容器必须 `min-width: 0`，避免文本/列表/弹层把容器撑爆
3. 滚动原则：外层负责占位和高度约束，内层负责真实滚动与滚动事件监听

```scss
.page-shell {
  display: flex;
  width: 100%;
  height: 100%;
  overflow: hidden;
}

.page-main {
  flex: 1;
  min-width: 0;
  min-height: 0;
  display: flex;
  flex-direction: column;
}

.page-scroll {
  flex: 1;
  min-height: 0;
  overflow: auto;
}
```

### 2.4 响应式适配

- 使用 `clamp()` / `minmax()` / `max()` / `min()` 处理侧栏、卡片、内容区宽度
- 避免把核心流程建立在"宽屏下才看得到"的 hover 交互上
- 三栏页面在窄窗口下应支持覆盖式或折叠式退化

```scss
.session-panel {
  width: clamp(220px, 24vw, var(--dt-session-panel-width));
  min-width: 220px;
  max-width: 280px;
}
```

## 三、性能优化清单

| 优化项 | 实施方式 | 优先级 |
|--------|---------|--------|
| 大列表 v-memo | `v-memo="[message.id, message.content]"` 消息项 | P0 |
| 图片懒加载 | IntersectionObserver 触发加载 | P0 |
| 组件异步加载 | `defineAsyncComponent` 用于弹窗/抽屉 | P1 |
| CSS containment | `content-visibility: auto` 用于折叠面板 | P1 |
| 防抖 & 节流 | 搜索输入 300ms debounce、滚动 16ms throttle | P0 |
| 事件解绑 | `onUnmounted` 中 removeEventListener | P0 |
| Web Worker | 消息加密/RRULE 解析移至 Worker | P2 |
| 路由拆包 | 各模块独立 chunk，首屏仅加载核心模块 | P0 |
| 稳定 props | 避免在模板中直接传对象字面量，使用 computed 缓存 | P1 |
| 全局监听成对清理 | 定时器/WebSocket 订阅在 `onUnmounted` 中清除 | P0 |

## 四、大模型开发前端约束（旧 doc75 恢复）

### 4.1 强制规范

1. **先搜现有组件，再新增实现**：页面/抽屉/列表/输入区/对话框优先复用已有结构
2. **样式必须先落 token 再落组件**：若发现缺 token，应先补 token，再改页面
3. **布局先定义容器，再定义内部块**：先回答"谁是滚动容器、谁负责伸缩、谁负责最小宽度"
4. **页面必须显式声明空/错/载入状态**：loading/empty/error/disabled/hover/focus 六态必须覆盖
5. **交互入口必须具备闭环**：任一按钮、图标、hover 工具条都要验证"点下去后是否真的有路径和反馈"
6. **响应式必须写退化策略**：窄窗口下哪些区域缩放、折叠、覆盖或隐藏
7. **全局监听、定时器、WebSocket 订阅必须成对清理**

### 4.2 设计令牌优先

所有颜色、字号、圆角、间距、阴影都应优先来自 `src/styles/design-tokens.scss`。页面组件可以组合 token，但不能另建隐式 token 体系。

**推荐写法**：

```scss
.panel {
  background: var(--dt-bg-card);
  border: 1px solid var(--dt-border-light);
  border-radius: var(--dt-radius-lg);
  box-shadow: var(--dt-shadow-1);
}
```

**禁止写法**：

```scss
.panel {
  background: #fff;
  border: 1px solid #e5e7eb;
  border-radius: 10px;
  box-shadow: 0 10px 30px rgba(0, 0, 0, 0.12);
}
```

### 4.3 可访问性约束

- 所有交互按钮必须可键盘聚焦
- `:focus-visible` 必须保留，不得仅依赖 hover
- 动画与过渡应尊重 `prefers-reduced-motion`
- 图标按钮必须具备 `title`、`aria-label` 或明确文本语义
