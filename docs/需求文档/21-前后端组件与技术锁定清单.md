## 三、引入新依赖的审批流程

```text
1. 在 PR 描述中写明：为什么现有 X 库不够用？
2. 对比：为什么不选现有锁定清单中的 Y？
3. 经 Owner 口头确认后才可合并
4. 合并后必须更新本清单（`21-前后端组件与技术锁定清单.md`）
```

> 违反此清单的 AI 生成代码 = 拒绝合并。已经写好的代码需在 code review 中打回。
