## 三、C 类（P1 — 结构性缺陷与规范缺失）

### C1. `design-tokens.scss` 源文件缺失 — 规范无锚点

doc 11/12/13/21 **全部**引用 `ruoyi-im-web/src/styles/design-tokens.scss` 为 token 源文件：

| 文档 | 引用行 |
|------|--------|
| `12` L7 | `Design Tokens 映射：ruoyi-im-web/src/styles/design-tokens.scss` |
| `13` L7 | `Token 源：ruoyi-im-web/src/styles/design-tokens.scss` |
| `21` 1.13 | `设计变量 var(--dt-*)` |
| `arch/13` 骨架代码 | 引入 `@/styles/design-tokens.scss` |

**实际情况**：

- `ruoyi-im-web/` 目录在 repository 中 **不存在**（top-level 仅有 prototype/、sql/、electron/ 等）
- `prototype/shared.css` 仅有少量 `--dt-*` token 的 demo 实现，非生产级 Design Token 文件
- B1 中列出的硬编码色值部分在 prototype/shared.css 中已有对应 token，但规范文档未引用 `prototype/shared.css` 作为 token 源

**影响**：所有引用 `design-tokens.scss` 的实现都不可落地。Token 映射断裂 = AI 生成代码时无规范可遵循。

### C4. doc 02 待核实项未关闭 — 兼容性风险未消除

| 待核实项 | 风险等级 | 影响 |

| TypeScript 严格模式 | 中 | 影响代码质量但不阻塞构建 |

doc 18 + doc 21 均断言兼容，但**没有任何文档给出兼容性证据**（如 pom.xml 实测、release notes 引用）。
