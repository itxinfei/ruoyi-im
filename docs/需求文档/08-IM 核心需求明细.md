# 08 IM 核心需求明细

> **定位**：消息、会话、通话、搜索、收藏 —— IM 主链路的完整大模型可执行明细（Execution-Ready）。
> **更新时间**：2026-10-27
> **基线对齐**：钉钉 Windows 客户端 8.2.0
> **实现前提**：单体 Java 后端（JDK 25 + Spring Boot 4.1.1）+ Vue 3 + TypeScript 前端

---

## 一、模块总览

### 1.1 模块定位

消息模块是产品主链路。目标是让用户稳定完成：

1. **找到会话** → 左侧会话列表
2. **查看消息** → 聊天区气泡流
3. **发送消息** → 输入区 + 上传
4. **搜索消息** → 会话内 + 全局
5. **协作辅助** → 通话、收藏、链接卡片

> **原则**：功能闭环优先于复杂架构；IM 是所有业务的驱动引擎。

### 1.2 模块边界

| 范围 | 包含 |
|------|------|
| ✅ 本模块覆盖 | 会话列表、聊天区、输入区、搜索、群详情、群文件、通话入口、消息收藏 |
| ❌ 本模块不要求 | 工作台协作闭环、开放平台、社交能力（朋友圈/动态） |

### 1.3 平台级导航要求

产品必须具备钉钉式一体化导航，左侧一级模块共 13 个：

`消息 → 搜索 → 通讯录 → 工作台 → 云盘/文档 → 日历 → 待办 → 审批 → 邮箱 → AI 助手 → 设置 → 个人资料 → 管理入口`

> **红线**：不允许长期保留空白承接页或"开发中"占位。每个展示的一级模块必须有真实可用页面。

## 三、消息生命周期状态机

### 3.1 发送状态机（必须严格遵循）

```
PENDING → SENDING → SENT → DELIVERED
                     ↘ FAILED
```

| 状态 | 常量 | 定义 | UI 表现 |
|------|------|------|---------|
| 待发送 | `PENDING` | UI 创建占位，消息进入本地队列 | Loading 旋转动画 + 半透明气泡 |
| 发送中 | `SENDING` | WebSocket 已发出，等待 ACK | Loading 旋转动画 |
| 已发送 | `SENT` | 服务端已确认（收到 ACK） | 正常气泡，无图标 |
| 已送达 | `DELIVERED` | 消息已推送到接收方 | 单勾图标 |
| 已读 | `READ` | 接收方已打开/阅读 | 双勾图标 |
| 发送失败 | `FAILED` | 超时（5s 未收到 ACK）或异常 | 红色警告图标 + 重试按钮 |

> **应用层 ACK 要求**：客户端通过 WS 发送消息后 5 秒内未收到 `message_ack` 帧，必须自动转为 `FAILED` 状态并提示用户重试。

### 3.2 操作状态机

| 操作 | 前置条件 | 时限 | 服务端动作 | UI 结果 |
|------|---------|------|------------|---------|
| 撤回 REVOKE | 消息状态=SENT | 发送后 < 2min | 推送 REVOKE 帧 | 全员气泡替换为"你撤回了一条消息" |
| 编辑 EDIT | 消息状态=SENT | 发送后 < 5min | 推送 EDIT 帧 | 全员实时替换内容，显示"已编辑"标记 |
| 转发 FORWARD | 消息已发送 | 无 | 创建新消息记录 | 选择目标会话/群组 |
| 删除 DELETE | 任意状态 | 无 | 软删除标记 | 本地移除气泡 |
| 收藏 FAVORITE | 消息已发送 | 无 | 写入 im_message_favorite | 无 UI 变化（收藏列表面板可见） |
| 回应 REACTION | 消息已发送 | 无 | 写入 im_message_reaction | 气泡下方显示emoji |

## 六、输入区

### 6.1 功能目标

用户可发送文本、图片、文件、语音消息。

### 6.2 主流程

1. 用户输入文本 → Enter 发送，Ctrl+Enter/Cmd+Enter 换行
2. 点击图片按钮 → 打开文件选择器 → 预览 → 上传 → 发送 IMAGE
3. 点击文件按钮 → 打开文件选择器 → 上传 → 发送 FILE
4. 粘贴图片/文件 → 自动识别 → 进入上传流程
5. 拖拽文件到聊天区 → 高亮提示释放 → 上传
6. 群聊输入 `@` 或点击 @ 按钮 → 拉起成员选择器
7. 存在回复上下文时 → 发送时带上 `replyToMessageId`

### 6.3 草稿逻辑

1. **自动保存**：用户输入但未发送 → 切换会话/关闭页面时保存至服务端（PUT /im/session/draft/{convId}），多设备同步
2. **回显**：切回会话时自动恢复输入框内容
3. **会话列表提示**：有草稿的会话项显示红色 `[草稿] xxx`
4. **清空**：发送成功后清除对应草稿

> **草稿存储**: 服务端持久化（PUT /im/session/draft/{convId}），多设备同步。浏览器 localStorage 仅作离线写入的临时写入缓冲（上线后优先读取服务端）。

### 6.4 异常流程

| 场景 | 处理方式 |
|------|---------|
| 未选择会话 | 输入区灰显，不允许输入 |
| 文件超限（>100MB） | Toast 提示"文件大小不能超过 100MB" |
| 上传失败 | 气泡内保持失败状态 + 红色警告 + 点击重试 |
| URL 解析失败/超时 | 降级为普通文本消息 |

### 6.5 语音消息规范

> ✅ 已确认

1. **交互流程**：点击录音图标 → 弹出录音小窗 → 松开/点击结束 → 上传 → 发送 VOICE
2. **最大时长**：60 秒（超时自动停止）
3. **展示**：气泡内波形图 + 时长，点击播放/暂停
4. **转文字**：右键"转文字" → 调用 `/api/im/voice/transcript` → 气泡下方显示结果
   - ⚠️ **走 `VoiceTranscriptProvider` 适配器**：内网无 ASR 服务时菜单项隐藏/置灰并提示"服务未配置"，**不得阻断主流程**（见 `18` 第五节）

### 6.6 验收标准

- AC1：文本消息发送瞬间立即出现 PENDING 状态气泡（零延迟体感）
- AC2：图片/文件发送前有进度条反馈
- AC3：群聊 @ 成员可选择，选中后输入框显示 `@姓名`
- AC4：回复消息可带上引用关系，点击引用可定位原消息
- AC5：粘贴图片自动触发上传链路
- AC6：超时 5s 状态变为 FAILED，气泡展示重试交互

### 6.7 @提及渲染算法

**消息发送时**：
1. 解析消息文本中的 `@用户名` 提及标记
2. 构建 `mentions: [{userId, userName, position}]` 数组
3. 消息存储时保留 mentions 数组

**消息渲染时（前端 ChatMessageBubble 内）**：

```javascript
function renderMessageText(text, mentions) {
  // Step 1: 全量 HTML 转义防 XSS
  let safeText = escapeHtml(text);

  // Step 2: 按 mentions.position 从高到低替换（避免索引偏移）
  mentions.sort((a, b) => b.position - a.position).forEach(m => {
    const tag = `<span class="mention-tag" data-user-id="${m.userId}">@${m.userName}</span>`;
    safeText = safeText.substring(0, m.position) + tag + safeText.substring(m.position + m.userName.length + 1);
  });

  return safeText;
}
```

**@选择面板 UI**：

```
+-----------------------------+
| 🔍 搜索成员...               |
+-----------------------------+
| 👤 全员 (@所有人)            |
| ---------------------------- |
| 👤 张三 · 产品部             |
| 👤 李四 · 研发部             |
| 👤 王五 · 设计部             |
+-----------------------------+
```

- 搜索框高 32px、右侧放大镜图标
- 列表项高 48px、左侧头像 32px + 姓名 14px + 职务 12px 灰色
- 键盘↑↓选择、Enter 确认、Esc 关闭
- 点击成员插入 `@姓名 ` 到输入栏（姓名后加空格，光标在空格后）

## 八、搜索（会话内 + 全局）

### 8.1 功能目标

用户可在会话内定位消息，或全局快速检索联系人、群组、文件。响应时间 ≤ 500ms。

### 8.2 入口处

1. 会话栏顶部搜索框 → **全局搜索**（跳转 SearchPanel）
2. 聊天头部搜索按钮 → **会话内搜索**（当前会话内）

### 8.3 核心逻辑

| 搜索范围 | 检索表 | 结果分类 |
|---------|--------|---------|
| 会话内 | `im_message`（按 conversationId 过滤） | 消息 |
| 全局 | `im_conversation`、`sys_user`、`im_group`、`im_file` | 消息/联系人/群组/文件 |

> **检索实现（决策定版）**：一期用 **MySQL 8 全文索引 + 分词**实现，检索逻辑收敛到**独立 DAO**，二期可平滑替换为 Elasticsearch / OpenSearch，业务层不感知。

| 场景 | 方案 | 说明 |

## 十二、WebSocket 实时协议

### 12.1 帧结构

```json
{
  "type": "MESSAGE | CALL | NOTIFY | EVENT | AUTH",
  "action": "SEND | RECEIVE | ACK | PING | PONG | REVOKE | EDIT",
  "requestId": "uuid",
  "data": { /* 业务载荷 */ },
  "timestamp": 1730000000000
}
```

### 12.2 心跳机制

| 项 | 值 |
|----|-----|
| 客户端发送间隔 | 30 秒 |
| 服务端超时判定 | 90 秒 |
| PONG 等待 | 发送 PING 后 5 秒 |
| 连续失败熔断 | 3 次 |

### 12.3 ACK 确认

| 类型 | 帧格式 |
|------|--------|
| 发送方 → 服务端 | `type=message, action=send` |
| 服务端 → 发送方 | `type=message, action=ack`（含 `clientMsgId` + `messageId`） |
| 服务端 → 接收方 | `type=message, action=receive` |
| 接收方 → 服务端 | `type=message, action=ack`（送达确认） |

### 12.4 离线消息

1. 消息先落库（`im_message`），再推送
2. 用户重连后发送 `type=message, action=sync`（携带 lastMessageId）
3. 服务端返回 lastMessageId 之后的所有未送达消息
4. 客户端逐条渲染 + 发送送达确认

## 十三、微交互与鲁棒性准则（IM 核心灵魂）

### 13.1 微交互准则

| # | 准则 | 说明 |
|---|------|------|
| UX-1 | 瞬时反馈 | 点击发送后消息立即进入聊天区（PENDING），不等待后端 |
| UX-2 | 气泡律动 | 新消息进入时有位移+淡入过渡，禁止生硬刷新 |
| UX-3 | 自适应感知 | 输入框高度随内容平滑撑开，最大 ≤ 聊天区高度 40% |
| UX-4 | 悬浮态感知 | 消息气泡 Hover 显示操作点（撤回/编辑/转发/更多），非 Hover 保持洁净 |

### 13.2 鲁棒性准则

| # | 准则 | 说明 |
|---|------|------|
| AR-1 | 消息去重 | 根据 `clientMsgId` 严格去重，防止 WS 与 HTTP 双重渲染 |
| AR-2 | 乐观更新 | 编辑消息先本地替换内容，报错则回滚 + Toast |
| AR-3 | 断网队列 | 离线时发送动作存入本地队列，恢复后原子化重试 |
| AR-4 | 版本号校验 | WS 的编辑/撤回指令必须带版本号，防旧数据覆盖新数据 |
| AR-5 | 超时熔断 | 5s 无 ACK 自动转 FAILED |
| AR-6 | **服务端序号排序** | 客户端**按服务端序号排序，禁止按客户端时间戳排序**（时钟偏移会致因果倒置） |
| AR-7 | **游标分页** | 历史消息用 `msg_id > cursor`，**禁用 OFFSET 深翻页** |
| AR-8 | **缺口检测** | 收到非连续序号时主动补拉，**不得静默丢消息** |
| AR-9 | **抖动重连** | 重连间隔加随机抖动，防重连风暴（Slack 2021 故障教训） |
| AR-10 | **群聊读扩散** | 禁按成员数写扩散（存储放大 50–500 倍） |
| AR-11 | **回执批量上报** | 高频群聊下定时批量压缩上报，避免回执反噬主通道 |

## 十七、核心约束与边界规则

### 17.1 消息长度与类型约束

| 约束项 | 值 | 错误码 | 说明 |
|--------|-----|--------|------|
| TEXT 最大字符数 | 5000 (UTF-8) | 10004 | 超出禁止发送提示"消息超长请分条或转文件" |
| 单条消息最大 Size | 1MB (含序列化) | 10013 | 超过降级为离线HTTP，不走 WS |
| msg_type 枚举 | TEXT/IMAGE/FILE/VOICE/VIDEO/LINK/LOCATION/GEOTAG/DING/SYSTEM/RECALL | — | DDL 必须包含全量 11 种，禁止截断 |

### 17.2 WebSocket 连接约束

| 约束项 | 值 | 说明 |
|--------|-----|------|
| 最大重连次数 | 15 次 | attempt<4: delay=2^attempt×1000+rand(0,500)ms; attempt≥4: 固定 30s; attempt≥15: 弹"网络异常"提示 + 切换 HTTP 轮询 |
| 单次心跳超时 | 30s | 连续 3 次无 PONG 共 90s 判定断连 |
| 离线消息上限 | 10,000 条/用户 | 超出 FIFO 丢弃最早；离线消息 TTL 30 天 |
| WS Token 过期 | AUTH_EXPIRED 帧 | 客户端 5s 内 refresh 重连；refresh 也过期则 close(4001) 跳转登录；多设备最多 3 个同时在线 |

### 17.3 API 速率限制

| 操作 | 限制 |
|------|------|
| IM 消息发送 | 30 次/秒 (滑动窗口), burst 60 | HTTP 429 + error_code 10009 |
| 全局搜索 | 10 次/分钟 | — |
| 会话创建 | 5 次/分钟 | — |
| 文件上传 | 3 次/分钟 (并发) | — |

### 17.4 消息操作时限

| 操作 | 时限 | 计时基准 | 冲突策略 |
|------|------|----------|----------|
| 撤回 (RECALL) | 2 分钟 (120s) | 服务端 message.create_time | 恰好 120s 可执行，超过 1ms 拒 + error_code 10002 |
| 编辑 (EDIT) | 5 分钟 (300s) | 服务端 message.create_time | 乐观锁：latest version 匹配才允许编辑，冲突 409 |

### 17.5 删除与软删

消息删除策略：
- DELETE 操作 = 服务端软删 (im_message.deleted = 1) + 客户端本地移除气泡（双写）
- 软删仅影响当前用户视图，不影响其他会话成员
- 删除通过 WS `deleted_notify` 帧推送给所有在线接收方
- 离线同步时 deleted=1 的消息不投递
- 换设备重装后，软删状态从服务端同步

### 17.6 草稿保存策略

会话草稿保存：
- 优先级：localStorage → IndexedDB → 内存（隐私模式）
- 单条上限：10,000 字符
- localStorage 总上限：≤ 2MB（LRU 淘汰最早草稿）
- 发送后立即异步清除本地草稿 + 同步服务端
- 多设备切换会话时拉取服务端 `/im/session/{convId}/draft` 覆盖本地缓存
- 服务端为主（im_session_draft 表），localStorage 为离线读缓存

### 17.7 DING 确认与过期

| 约束项 | 值 | 说明 |
|--------|-----|------|
| 提醒频率 | 每 5 分钟一次，最多 3 次 | 应用内居中强制弹窗 + 列表项置顶 |
| 完成条件 | 全员 50% 确认 或 COMPRESSED | 标记为 COMPLETED |
| 过期条件 | deadline 到达且未完成 | 服务端每 10 分钟一次定时扫描 |
| deadline 范围 | 当前时间 +1h ~ +72h (3天) | 超出范围返回 error_code 10014 |

### 17.8 通话约束

| 约束项 | 值 |
|--------|-----|
| 群会议产品上限 | 9 人 (LiveKit 无技术限制，9 人为产品上限) |
| 第 10 人加入 | WS reject + error_code 10008 (房间已满) |
| 通话超时 | 30s 无应答 TIMEOUT，所有人生成零时长记录 |
| 断线重连 | 3s 内 ICE Restart，最大尝试 3 次，失败降级仅音频 |
| 录制存储 | MinIO + LifecyclePolicy (保留 90 天) |
