## 二、技术选型最终定版

### 2.1 总表

| 层 | 选型 | 备注 |
|----|------|------|
| **后端运行时** | JDK 25 | 不回退 |
| **后端框架** | Spring Boot 4.1.1 | 命名空间 `jakarta.*` |
| ORM / 安全 | MyBatis Plus / Spring Security + JWT | |
| **前端** | Vue 3 + TypeScript + Vite + Element Plus + Vuex 4 | 禁纯 JS 业务文件 |
| **桌面端** | **Electron** + electron-builder | 复用同一套 Vue 代码 |
| **关系库** | MySQL 最新 8.x LTS | 雪花主键，禁自增 |
| **缓存** | Redis 最新稳定版 | key 前缀 `im:` |
| **对象存储** | **MinIO**（S3 兼容） | 附件一律走 MinIO，不入库 |
| **检索** | **MySQL 8 全文索引**（一期） | 预留 ES / OpenSearch 接入点 |
| **消息总线** | **Redis Pub/Sub**（一期） | 二期可换 RocketMQ / Kafka |
| **实时通信** | 原生 WebSocket | JSON 帧，心跳/重连/弱网队列 |
| **通话媒体** | 浏览器 WebRTC + **LiveKit SFU** | Java 侧只签发 JWT + 调 REST API |
| **会议录制** | **LiveKit Egress** | 存 MinIO，永久保留 |
| **NAT 穿透** | LiveKit **内置 TURN** | 独立 coturn 为备选 |
| **文档在线编辑** | **ONLYOFFICE Docs**（≥9.4） | 支持 docx/xlsx/pptx，JWT 鉴权嵌入 |
| **部署** | Docker + Nginx | Maven / npm 构建 |

### 2.2 通话媒体栈选型依据

**LiveKit**（Go，18k+ stars，2026 年自建 SFU 主流选择）对比其他方案：

| 方案 | 语言 | 为何选 / 不选 |
|------|------|--------------|
| **LiveKit（选定）** | Go | 内置信令、房间管理、**内置 TURN**、Redis 集群、SDK 全、Docker 一键、学习曲线低 |
| mediasoup | C++ + Node | 性能最强，但**无内置信令**需自建，且要写 Node 媒体层 |
| Janus | C | 强在 SIP 电话互通，本项目无此需求 |
| Jitsi | Java/Kotlin | 开箱完整但定制难，JVM GC + Netty 单线程瓶颈 |
| SRS | C++ | 国产中文文档好，但偏直播场景；**国产化要求高时作备选** |
| Pion | Go | 是库不是成品 SFU，自研到生产需 1 年以上 |

**关键收益**：Java 团队**不写一行媒体层代码**，只负责签发 JWT 与调用 REST API 创建房间。

### 2.3 消息可靠性机制（强制，来自业界教训）

| 机制 | 要求 |
|------|------|
| 服务端分配序号 | 客户端**按序号排序**，禁用客户端时间戳排序（时钟偏移致因果倒置） |
| 游标分页 | `WHERE conversation_id=? AND msg_id > ?`，禁 OFFSET 深翻页 |
| 缺口检测 | 序号不连续时主动补拉，不得静默丢消息 |
| 应用层 ACK | TCP 发送成功 ≠ 对端收到，必须应用层确认 |
| 抖动重连 | 重连间隔加随机抖动（Slack 2021 故障教训） |
| 消息幂等 | 按 `clientMsgId` / `message_id` 去重 |
| 群聊读扩散 | 禁按成员数写扩散（存储放大 50–500 倍） |
| 回执批量上报 | 高频群聊下定时批量压缩上报 |

## 三、IM 核心功能：做 / 不做

> 编号沿用 `08-IM 核心需求明细.md`

### 3.1 消息类型

| 类型 | 结论 | 说明 |
|------|------|------|
| TEXT 文本 | ✅ 做 | 含 URL 自动识别（纯文本链接） |
| IMAGE 图片 | ✅ 做 | 存 MinIO，三级加载 缩略图→高清→原图 |
| FILE 文件 | ✅ 做 | MinIO + 分片（5MB/片）+ 断点续传 |
| VOICE 语音 | ✅ 做 | ≤60s，波形+时长；**转文字 → 适配器降级** |
| VIDEO 视频 | ✅ 做 | 存 MinIO |
| LOCATION 位置 | ⚠️ **降级做** | 存坐标 + 地点名称文本，**不渲染地图瓦片** |
| CARD 名片 | ✅ 做 | |
| DING | ✅ 做 | **提醒方式仅"应用内"**；短信 / 电话外呼不做 |
| SYSTEM 系统通知 | ✅ 做 | |

### 3.2 会话列表（IM-S-001 ~ 010）

**全部做**：列表展示、置顶、免打扰、删除、未读数、会话搜索、排序、草稿保存、会话分组、批量操作。

### 3.3 聊天区（IM-D-001 ~ 012）

| 编号 | 需求 | 结论 |
|------|------|------|
| D-001 ~ D-005 | 气泡渲染 / 时间 / 历史加载 / 定位跳转 / 链接识别 | ✅ 做 |
| **D-006** | **链接卡片预览** | ⚠️ **降级做**：走 `LinkPreviewProvider`，仅解析内网可达地址；超时 3s 或不可达 → 降级为纯 URL |
| D-007 ~ D-012 | 图片预览 / 文件预览 / 搜索高亮 / 多选 / @高亮 / 已读回执 | ✅ 做 |

### 3.4 输入区与上传

- 输入区（文本/表情/文件/图片/语音/@/引用/草稿）✅ 全做
- 上传 IM-U-001 ~ 007（点击/拖拽/粘贴/进度/重试/分片/断点续传）✅ 全做

### 3.5 搜索（IM-SE-001 ~ 008）

✅ 全做。一期用 **MySQL 全文索引 + 分词**实现会话内与全局搜索，检索走独立 DAO，二期可平滑换 ES。

### 3.6 群详情与群管理（IM-G-001 ~ 010）

✅ 全做：群信息、成员列表、公告、成员管理、群主转让、禁言、二维码、退出解散、群文件面板、个人备注。

| C-008 | 最小化悬浮窗 | ✅ 做 |
| C-009 | 通话记录 | ✅ 做 |

## 五、内网服务对接：可插拔适配器策略

| 能力 | 适配器接口 | 决策 | 降级行为 |
|------|-----------|------|---------|
| 语音转文字 ASR | `VoiceTranscriptProvider` | **仅占位，不接** | 菜单项隐藏或置灰，提示"服务未配置" |
| 链接卡片解析 | `LinkPreviewProvider` | 仅解析内网可达地址 | 降级为纯 URL 文本（超时 3s 同降级） |
| 位置地图 | `GeoProvider` | **仅占位，不渲染地图** | 仅存坐标与名称文本 |
| **AI 助手** | `AiProvider` | **接内网已有模型服务** | 未配置时显示"未接入模型服务" |
| **邮箱收发** | `MailProvider` | **接企业内网邮件服务器** | 未配置时显示"未配置邮件服务" |
| DING 外部提醒 | `NotifyProvider` | **仅占位，不做短信/电话** | 仅保留应用内提醒 |
| Office 在线编辑 | `OfficeProvider` | **接 ONLYOFFICE Docs** | 服务不可用时回退为"仅下载/预览" |

**红线**：每个适配器必须有**接口 + NoOp 空实现**；业务层只依赖接口；服务地址与密钥**一律走配置文件**，**禁止硬编码**。

### 5.1 待补充的连接信息

| 服务 | 协议假设 | 需你提供 |
|------|---------|---------|
| 企业邮件服务器 | **IMAP / SMTP** | 地址、端口、加密方式（SSL/TLS/STARTTLS）、鉴权方式、是否需域账号 |
| 内网模型服务 | **OpenAI 兼容接口** | base_url、鉴权方式（API Key / Token）、模型名称 |

> 若邮件实际为 **Exchange（EWS / Microsoft Graph）**，只需替换 `MailProvider` 实现，接口不变。

### 5.2 仅 OFFICE 选型依据（云盘在线编辑）

| 维度 | ONLYOFFICE Docs（选定） | Collabora Online |
|------|------------------------|------------------|
| 内核 | 自研 OOXML 引擎 | LibreOffice 内核 |
| MS 格式保真 | **优秀**（OOXML 原生，不转换） | 良好（ODF 优先，复杂排版可能偏移） |
| UI 体验 | **接近 Microsoft Office**，国内用户零培训 | 偏 LibreOffice 传统风格 |
| Java 团队接入 | **API 文档完整，接入直接** | 需自实现 **WOPI 协议**，门槛高 |
| 架构（9.4 后） | **单进程，已移除 RabbitMQ / DB 依赖** | 单容器，基线内存 ~1.3GB |
| 并发 | **9.4 起取消社区版 20 并发上限** | 无限制 |

> ⚠️ 网上多数对比基于 9.4 之前版本（"需五服务 + 限 20 并发"）**已过时**。
> **国产化备选**：有信创要求时评估 WPS 政企私有化 / 永中 Office，替换 `OfficeProvider` 实现即可。

## 六、明确不做（Out of Scope）

以下**本期明确不纳入**，避免范围失控：

| 不做项 | 原因 |
|--------|------|
| **移动端原生 App**（Android / iOS / 鸿蒙） | 定位是 PC 端钉钉式平台，桌面端 Electron 已覆盖 |
| **开放平台 / ISV 应用市场** | 超出内网协同定位 |
| **社交功能**（朋友圈、动态、附近的人） | 非企业协同场景 |
| **端到端加密**（E2EE / Signal 协议） | 企业内网场景需**消息留痕与审计**，与 E2EE 冲突 |
| **跨组织联邦互通**（Matrix 协议） | 单组织内网部署，无跨企业互联需求 |
| **多租户 SaaS 形态** | 私有化单租户 |
| **DING 短信 / 电话外呼** | 内网无短信网关与电话线路 |
| **小程序** | 同移动端，不在本期 |
| **阅后即焚** | 与管理后台"消息审计/留痕"要求冲突 |
| **Kafka 全量消息流水 / Cassandra / ScyllaDB** | 规模不匹配（10–500 人），属过度工程 |
