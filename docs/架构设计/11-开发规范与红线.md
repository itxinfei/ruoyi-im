# 11 开发规范与红线

> **定位**：定义全局编码红线、模块间通信约束、依赖使用规范、Code Review Checklist。
> **更新时间**：2026-10-30

---

## 一、全局红线 (违反即拒绝合并)

### 1.1 数据库红线

| 红线 | 说明 |
|------|------|
| 禁止原生 SQL 拼接 | MyBatis 必须参数化 (`#{}`), 禁 `${}` 拼接用户输入 |
| 禁止物理删除 | 全部使用 `del_flag` 逻辑删除 + `@TableLogic` |
| 禁止 AUTO_INCREMENT | 主键策略统一 `IdType.ASSIGN_ID` (雪花 ID) |
| 禁止单表全量查询 | 必须分页, 分页使用游标方式 (禁 OFFSET 翻页超 10000 行) |
| 禁止 N+1 查询 | 循环内禁止单条 SQL 查询, 必须批量查 |
| 禁止无索引查询 | WHERE 条件字段必须建索引, EXPLAIN 验证 |
| 禁止大事务 | 单事务不超过 50 次 DB 操作, 长事务需拆分 |

### 1.2 安全红线

| 红线 | 说明 |
|------|------|
| 禁止明文日志 | 密码/Token/手机号/身份证不得打印到日志 |
| 禁止无鉴权 | 所有 REST 接口必须有鉴权 (OpenAPI 白名单除外) |
| 禁 JWT 硬编码 | 私钥必须来自配置中心或环境变量, 禁止写入代码仓库 |
| 禁跨域宽松 | `Access-Control-Allow-Origin` 必须是白名单域名, 禁 `*` |
| 禁直接渲染 | 所有用户输入内容必须经过 sanitize (JSoup/DOMPurify) |
| 禁反射调用 | 业务代码禁 `Method.invoke` 执行用户可控方法名 |

### 1.3 服务间通信红线

| 红线 | 说明 |
|------|------|
| 禁止服务直连 DB | 各服务只能通过自身 Mapper 访问所属数据库, 禁止访问其他服务的数据库 |
| 禁止同步循环依赖 | A→B→A 的同步调用链禁止; 循环依赖通过异步 MQ 解决 |
| 禁止超长事务 | 跨服务调用禁止包含本地 DB 事务 (考虑 Saga/TCC) |
| 禁无超时 | 所有 Feign/HTTP 调用必须设置超时 (connect ≤ 3s, read ≤ 10s) |
| 禁无限重试 | 跨服务调用重试 ≤ 3 次, 指数退避, 需幂等 |

### 1.4 前端红线

| 红线 | 说明 |
|------|------|
| 禁止直接 new WebSocket | 必须通过 `useImWebSocket` 统一管理 |
| 禁止 Pinia | 全局状态必须使用 Vuex 4 |
| 禁止第二 UI 库 | 只能使用 Element Plus, 禁止引入 Arco/Naive/TDesign 等 |
| 禁止内联样式 | 颜色/字号/间距必须用 `var(--dt-*)` 设计变量 |
| 禁止未清理事件 | `onMounted` 注册的 WS/EventBus/Listener 必须在 `onBeforeUnmount` 中移除 |
| 禁止 v-html 直接渲染 | 必须 `DOMPurify.sanitize()` 后再渲染 |
| 禁止在组件内直接 HTTP | 必须封装到 `src/api/im/*.js`, 组件内通过 API 函数调用 |
| 禁止副作用超过 200 行 | Vue SFC 超过 200 行必须拆分组件/Composable/Store |

## 二、模块间通信约束

### 2.1 服务依赖矩阵 (允许方向)

```
im-gateway       → platform-user (JWT 鉴权 / 用户批量查询)
im-message       → im-session / platform-user / im-group / im-real-time (WS 推送)
im-session       → platform-user / im-message (最近消息)
im-real-time     → platform-user (鉴权) / im-group (群成员)
im-group         → platform-user (群成员校验)
collab-task      → platform-user (待办分配者 / 审批发起人)
collab-calendar  → platform-user / im-real-time (事件提醒)
collab-doc       → file-storage / platform-user (文档分享)
file-storage     → (独立,仅接受上传下载请求)
platform-user    → file-storage (头像上传)
admin-system     → platform-user (用户管理)
platform-ai      → (独立,MCP/LLM 后端)
platform-search  → (独立,ES 索引消费 MQ 事件)
```

### 2.2 交互方式选择

| 场景 | 方式 | 说明 |
|------|------|------|
| 实时性要求高 (< 100ms) | OpenFeign 同步调用 | Token 查询/用户信息 |
| 可容忍延迟 (秒级) | RabbitMQ 异步 | 状态广播/落库/推送 |
| 实时推送 | WebSocket | 新消息/状态变更 |
| 批量操作 | 批量 Feign API | 批量查用户/群信息 |
| 跨模块事件 | RabbitMQ Topic | 审计事件/操作日志 |

### 2.3 OpenFeign 配置规范

```java
@FeignClient(
    name = "platform-user",
    contextId = "userServiceClient",
    configuration = FeignConfig.class,
    fallbackFactory = UserClientFallbackFactory.class
)
public interface UserServiceClient {

    @GetMapping("/im/user/batch")
    Result<List<UserDTO>> batchGetUsers(@RequestParam("ids") List<Long> ids);

    @GetMapping("/im/user/{id}/simple")
    Result<UserSimpleDTO> getSimple(@PathVariable("id") Long id);
}

// 必须有 Fallback
@Component
public class UserClientFallbackFactory implements FallbackFactory<UserServiceClient> {
    @Override
    public UserServiceClient create(Throwable cause) {
        return new UserServiceClient() {
            @Override
            public Result<List<UserDTO>> batchGetUsers(List<Long> ids) {
                return Result.fail("用户服务不可用,显示占位信息");
            }
            @Override
            public Result<UserSimpleDTO> getSimple(Long id) {
                return Result.fail("用户服务不可用");
            }
        };
    }
}

// 超时配置

feign:

    config:
      default:
        connect-timeout: 3000
        read-timeout: 10000
        logger-level: basic
```

## 三、DDD 分层约束 (后端)

### 3.1 层间依赖方向

```
interfaces (Controller/WebSocket)
    ↓ DTO 转换
application (ApplicationService)
    ↓ Command/Query
domain (DomainService/Entity/ValueObject/Repository接口)
    ↓ 接口倒置
infrastructure (Repository实现/Mapper/外部客户端)
```

### 3.2 各层职责

| 层 | 允许 | 禁止 |
|----|------|------|
| **interfaces** | 参数校验、DTO 转换、调用 ApplicationService | 直接操作 Mapper、包含业务逻辑 |
| **application** | 编排领域服务、DTO 转换、发送 MQ 事件、处理事务 | 包含领域规则算法、直接 SQL |
| **domain** | 领域逻辑、值对象、领域事件定义、Repository 接口 | 依赖 Spring 框架、依赖 Mapper、依赖 HTTP 客户端 |
| **infrastructure** | Mapper/DAO 实现、Repository 实现、Feign 客户端、MQ 生产者 | 包含业务逻辑 |

### 3.3 领域实体规范

```java
// 正确: 领域行为在 Entity 内
@Data
@TableName("im_message")
public class Message extends BaseDomainEntity {

    private Long sessionId;
    private Long senderId;
    private MessageType type;
    private String content;
    private Long serverSeq;
    private MessageStatus status;
    private LocalDateTime sendTime;

    // 领域行为 (充血模型)
    public void recall() {
        if (this.status == MessageStatus.RECALLED) {
            throw new DomainException("消息已撤回");
        }
        if (Duration.between(this.sendTime, LocalDateTime.now()).toMinutes() > 5) {
            throw new DomainException("消息发送超过 5 分钟, 不可撤回");
        }
        this.status = MessageStatus.RECALLED;
        this.content = "消息已撤回";
    }

    public boolean isWithinRecallWindow() {
        return Duration.between(this.sendTime, LocalDateTime.now()).toMinutes() <= 5;
    }
}
```

## 五、Git 协作规范

### 5.1 分支策略

```
main          (生产分支, 保护)
├── release/* (预发布分支, 并行验证)
├── develop   (集成开发分支)
└── feature/* (功能分支, 从 develop 切出)
```

### 5.2 Commitizen 规范

```
feat(message): 新增消息转发功能
fix(session): 修复会话置顶状态丢失 (#123)
refactor(group): 群组权限逻辑拆分
perf(message): 消息历史查询优化, 游标分页替换 OFFSET
docs(api): 新增消息模块 API 文档
test(message): 补充消息撤回单测
chore(build): 升级 mybatis-plus 到 3.5.9
```

### 5.3 Code Review Checklist

#### 后端 CR 检查项

- [ ] 是否有 SQL 注入风险 (检查所有 `${}` 用法)
- [ ] 是否有 N+1 查询问题
- [ ] DTO 转换是否在 Application 层完成 (非 Domain 层)
- [ ] 是否有事务注解缺失或过大
- [ ] 是否有敏感信息泄露风险
- [ ] Feign 调用是否有 Fallback 和超时配置
- [ ] MQ 消息是否幂等 (去重键/唯一约束)
- [ ] 是否有内存风险 (大对象/无限增长的 List)
- [ ] 新增 API 是否有鉴权注解 (`@PreAuthorize`)
- [ ] 异常是否对用户友好, 不暴露内部异常栈

#### 前端 CR 检查项

- [ ] Vuex Store 模块是否有 `namespaced: true`
- [ ] DOMPurify 是否用于所有用户内容渲染
- [ ] WebSocket/EventBus 是否在 `onBeforeUnmount` 中取消订阅
- [ ] API 调用是否有统一错误处理 (axios 拦截器)
- [ ] 组件是否超过 200 行, 需要拆分
- [ ] 是否有内存泄漏 (定时器/全局事件未清理)
- [ ] 是否使用了内联样式 (颜色/字号/间距)
- [ ] TypeScript 类型是否完整 (禁止 `any` 滥用)
