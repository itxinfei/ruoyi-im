## 一、架构概览

**心飞IM 2.0** 是从零重构的企业级即时通讯与协同办公平台，对标钉钉 Windows 客户端，面向内网私有化部署（10-500 人规模）。

### 1.1 核心架构原则

| 原则 | 说明 |
|------|------|
| 微服务化 | 12 个独立微服务，按领域边界拆分，单服务可独立部署/扩缩容 |
| DDD 驱动 | 每个服务内部按接口层→应用层→领域层→基础设施层 四层架构 |
| Vuex 4 锁定 | 全局状态管理唯一使用 vuex（**禁用 Pinia**），按业务域拆分子模块 |
| 可插拔适配器 | 外网依赖能力（AI/邮箱/ASR/链接卡片）走接口 + NoOp 空实现 |
| 中间件解耦 | Redis Pub/Sub 跨节点广播 + RabbitMQ 异步事件 + Nacos 服务治理 |

## 五、关键架构约束（红线）

### 5.1 前端红线

1. 唯一状态库 **Vuex 4**（禁用 Pinia / MobX）
2. 唯一 UI 库 **Element Plus**（禁用任何其他 UI 库）
3. 唯一图标 **@element-plus/icons-vue**
4. 模块间通信只能通过 **EventBus / Vuex Store**，禁止跨模块直接 import
5. 禁止在组件内直接 `new WebSocket()`，必须走 `useImWebSocket`
6. 禁止纯 JS 业务文件（所有新文件必须 TypeScript）

### 5.2 后端红线

1. 单向调用链：Controller → ApplicationService → DomainService → Repository，禁止反向
2. Controller 禁止暴露 Entity（必须 DTO/VO）
3. WebSocket 端点禁止注入业务 Service，改为监听 DomainEvent
4. 禁止漏掉 NoOp 实现（所有 Provider 必须有空兜底）
5. 禁止服务循环依赖（必须有向无环图 DAG）

### 5.3 通信红线

1. 消息排序唯一使用 **serverSeq**，禁止客户端时间戳排序
2. API 统一前缀 `/im/`，禁止 `/api/` 和 `/im/` 双前缀并存
3. 微服务间同步调用统一端口分配（8081-8092）
