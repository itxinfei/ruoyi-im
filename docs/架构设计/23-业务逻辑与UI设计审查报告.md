## 一、核心业务对象标识一致性（P0 级）

### 问题：sessionId vs convId vs conversation_id 三词混用

| 层级 | 文档 | 当前命名 | 
|------|------|----------|
| 前端 Vuex | doc 02/13 | `convId` ✓ |
| WebSocket 协议 | doc 05 | `convId` ✓ |
| Redis Key | doc 04 | `{convId}` ✓ |
| 数据库字段 | doc 04 | `conversation_id` (SQL 层) |
| REST API 路径 | doc 03/06 | ~~`{sessionId}`~~ | 
| 后端 DTO/Service 签名 | doc 03 | ~~`sessionId`~~ |

**根因**：REST API 路径使用了 `{sessionId}`，与其他所有层不一致。

**修复（已完成）**：
- doc 03：`/im/session/{sessionId}` → `/im/session/{convId}`
- doc 03：`@PathVariable Long sessionId` → `@PathVariable Long convId`
- doc 06：API 表中 12 处 `{sessionId}` 全部 → `{convId}`
- doc 03 Redis SEQ：`session:seq` → `im:seq:{convId}`

**最终映射关系**：

```
前端 (Vue/ConvView)            WebSocket               REST API
─────────────────────          ─────────────           ──────────
sessionStore.currentConvId  ←→  frame.convId  ←→  GET /im/session/{convId}
messageStore.messageMap[convId] ← frame.convId  ←→  GET /im/message/history?convId=
```

## 三、消息状态机生命周期

### 当前定义

```
             ┌──────────────┐
             │   PENDING    │ DB: 0
             └──────┬───────┘
                    │ WS 发送到服务器
             ┌──────▼───────┐
             │   SENDING    │ DB: 1
             └──────┬───────┘
                    │ 服务器返回 ACK + serverSeq
             ┌──────▼───────┐
             │    SENT      │ DB: 2
             └──────┬───────┘
                    │ 接收端 WS 在线推送完成
             ┌──────▼───────┐
             │  DELIVERED   │ DB: 3
             └──────┬───────┘
                    │ 接收端触发 read_receipt 事件
             ┌──────▼───────┐
             │    READ      │ DB 无状态! ← 由 im_read_record 表记录
             └──────────────┘

        ┌────────────────────────────────────┐
        │   任意非终态 + 24h 内 + 发送者本人   │
        │   → RECALLED (DB: 9)              │
        └────────────────────────────────────┘
```

### 问题：READ 状态在消息表中不存在

| 已阅状态 | 存储位置 | 文档 |
|----------|----------|------|
| DELIVERED | `im_msg.status = 3` | doc 04 line 47 |
| READ | `im_read_record` 表 (多对多) | doc 04 line 73-82 |
| READ cursor | Redis `readCursor` per conv + per user | doc 02 line 221 |

**前端因此显示两套逻辑**：
- "对方已读" = `im_read_record` 表有记录
- "已读到 serverSeq" = `readCursor` 值（用于下次拉取时过滤）

**建议**：在 doc 05 WS 协议中添加说明：

```
已读状态不通过消息 status 字段维护,
而是通过 im_read_record 表 + readCursor 实现。
前端气泡"已读"标记 = 本地 readCursor >= msg.serverSeq
```

## 七、业务逻辑 Checklist

### 7.1 消息发送全链路

```
用户在 ChatInputArea 点击发送
     │
     ▼
ChatInputArea.handleSend()
     │
     ├─ 1. 生成 clientMsgId (uuid)
     ├─ 2. 生成 clientSeq (本地自增)
     ├─ 3. dispatch('im/message/sendMessage', cmd)
     │        │
     │        ├─ commit('ADD_MESSAGE', pendingMsg, { root: true })
     │        │     └─ status = 'SENDING' (前端乐观更新)
     │        │
     │        └─ window.dispatchEvent('im:ws:send', cmd)
     │              │
     │              ▼
     │        useImWebSocket.send(cmd)
     │              │
     │              ▼ [WS 帧]
     │        ┌─────────────────────────────────┐
     │        │ { "type":"MESSAGE",              │
     │        │   "action":"send",               │
     │        │   "data":{                       │
     │        │     "convId":123,                │
     │        │     "msgType":"TEXT",            │
     │        │     "content":"Hello",           │
     │        │     "clientSeq":42,              │
     │        │     "clientMsgId":"uuid-xxx"     │
     │        │   }                              │
     │        │ }                                │
     │        └──────────────┬──────────────────┘
     │                       │
     │                       ▼ [im-real-time 服务]
     │        ┌──────────────────────────────┐
     │        │ 1. JWT 鉴权 (从 token 取 userId)
     │        │ 2. 幂等检查 (去重 clientMsgId)
     │        │ 3. serverSeq = INCR im:seq:{convId}
     │        │ 4. DB INSERT im_msg
     │        │ 5. MQ 发布 msg.store 事件
     │        │ 6. WS 推送给在线群成员/聊天对方
     │        │ 7. 返回 ACK 帧
     │        └──────────────┬───────────────┘
     │                       │
     │                       ▼ [ACK 帧]
     │        ┌─────────────────────────────────┐
     │        │ { "type":"ACK",                  │
     │        │   "data":{                       │
     │        │     "clientMsgId":"uuid-xxx",    │
     │        │     "serverSeq":42,              │
     │        │     "serverTime":1730000000000   │
     │        │   }                              │
     │        │ }                                │
     │        └──────────────┬──────────────────┘
     │                       │
     │                       ▼ [前端处理 ACK]
     │        dispatch('im/message/ackReceived', ack)
     │        │
     │        ├─ 替换 pending 消息 ID
     │        ├─ commit('UPDATE_MSG_STATUS', { status: 'SENT' })
     │        └─ 从 sendingQueue 移除
     │
     └─ 4. ElMessage 通知 (发送成功/失败)
```

**已验证一致** ✓ — doc 05 WS 协议 ✓ — doc 13 Vuex Action ✓ — doc 03 后端处理流程

### 7.2 消息接收全链路

```
im-real-time 推送 receive 帧
     │
     ▼
WebSocket.onmessage → useImWebSocket.onWs('message')
     │
     ▼
bus.emit(EVENTS.MESSAGE_RECEIVED, msg)
     │
     ▼
ChatWindow 订阅 MESSAGE_RECEIVED
     │
     ├─ commit('ADD_MESSAGE', msg)  // im/message store
     ├─ 排序: 按 serverSeq 升序
     ├─ 检测消息连续性: |prevSeq - currSeq| > 1 → 触发 sync_gap
     └─ 发送 read_receipt (若当前会话可见)
```

**已验证一致** ✓ — doc 05 WS 帧格式 ✓ — doc 13 Composable ✓ — doc 11 EventBus

### 7.3 群聊消息链路

单聊 vs 群聊差异:

| 步骤 | 单聊 P2P | 群聊 Group |
|------|----------|------------|
| 群成员查询 | 无 | `group_member` 表查群成员 |
| WS 推送 | 推送给对方 1 人 | 推送给所有在线群成员 |
| 已读回执 | 双向已读 (已读互知) | 仅记录谁已读,不广播 |
| 未读计数 | `im:unread:{userId}:{convId}` | 同上 (per member) |
| 消息存储 | `im_msg` 表 1 行 | `im_msg` 表 1 行 (不重复存储) |

**建议**：doc 05 补充群聊广播 WS 推送的 QPS 控制 (群 500 人 = 500 次 WS frame 写)。
